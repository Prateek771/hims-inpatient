## Boundaries to preserve during implementation

Server Components read authorized records. Thin Server Actions and the required Route Handlers call feature-owned server commands. Role, active-account and state checks belong on the server. Shared money/state logic is deterministic and transactional; money is integer paise, and ledger corrections retain history.

The PostgreSQL foundation uses separate owner/runtime accounts for `hims_local` and `hims_test`, a lazy five-connection pool and reviewed migrations. Audit history records human or internal-job identity, request, source, reason, timestamp and entity versions; runtime privileges prohibit changing or deleting audit and setting-version rows. Feature modules extend `web/src/server/` and add new migrations under `web/drizzle/`; never rewrite applied migration bytes. See [database setup](docs/DATABASE_SETUP.md).

LangGraph uses its official PostgreSQL saver in a separately prepared checkpoint schema for bounded manual paperwork review. It cannot authorize clinical treatment, coverage, money or discharge seals. External insurers/TPAs and staff remain responsible for verification; payment-service integration is deferred.

Better Auth owns password hashing and database sessions; protected commands recheck current role and active status. Staff changes revoke sessions, and serialized administration preserves the last active administrator. Public signup and raw administrative auth endpoints are blocked. Settings append immutable versions with stale-edit protection. See [staff access](docs/STAFF_ACCESS.md). Persisted admissions establish scoped admission-desk, administrator operational and recorded-admitting-doctor reads. Nurses require a current non-revoked assignment; Pharmacy has purpose-limited medicine work access; LAB access is limited to actual diagnostic tasks and their needed identity/results; Insurance access requires its current persisted case assignment; Admin/Billing case authority remains purpose-limited. See [insurance](docs/INSURANCE.md).

Permanent patient identity, pending admission episodes and exclusive physical-bed holds exist. Registration/reservation does not start a room stay or charging; billing activation checks configured policies, patient deposit and actual occupancy before starting a tariff-pinned stay. Pending cancellation preserves identity, IP code and history. See [admission](docs/ADMISSION.md) and [current acceptance status](docs/agent/BUILD_HANDOFF.md).

Billing uses bigint paise, exact explicit-unit quantities and immutable charges, finalizations, reversals, receipts and allocations. Financial mutations serialize on their admission. Source identity prevents duplicate charges; separate cash identity protects against counting the same receipt under another retry key. Room reconciliation posts cumulative differences through a cutoff using persisted cursors. Transfers compose its transaction primitive; importing the worker never starts polling. See [billing](docs/BILLING.md). Pharmacy validates actual Doctor-selected identity, physical stock and actual receipt source, composing issue/return and original-price billing in one transaction. Native guards retain stock/movement/source invariants. See [Pharmacy](docs/PHARMACY.md). Lab human completion finalizes its original pending source once; unpriced reports remain with explicit financial work. A narrow stopped-unperformed disposition retains its original source reversal, and pending totals net linked reversals. See [Lab](docs/LAB.md). Externally verified payer responsibility and protected versioned case files exist; saved allocations bind economic sources while actual cash remains separate. Discharge uses four human seals with selective native/source invalidation, current responsibility and actual linked refunds. Nurse-attested room vacancy closes the priced stay; later actual hospital departure rechecks settlement and releases the hold into required cleaning. See [Discharge](docs/DISCHARGE.md).

Clinical and nursing modules persist immutable signed rounds/addenda, orders, summary/prescription versions, explicit scheduled occurrences, shifts/handover, observations, MAR and consumable sources. Current assignment and writes serialize on the admission; saved retry results still require current access. Ward and take-home medicine purpose is explicit, and signed dispensing quantities are separate from clinical dose units. Missing charge configuration retains clinical records with unresolved financial work. Pharmacy issue owns medicine charges; MAR does not duplicate them. See [care](docs/CARE.md). Pharmacy fulfillment uses its own source-linked projection and does not claim a regimen completed on first issue. Human diagnostic reports/addenda are visible to the assigned Doctor; new processing cannot follow a Doctor stop. Lab facts bind sample/order/patient with immutable identity and actual post-lock signing times. Formal Doctor → Pharmacy → Nursing → Billing seals retain coherent signed source snapshots. Financial clearance does not end monitoring or attendance. Native/app attendance guards protect recorded vacancy in both event orders. Accountable Admin authority and proper professional evidence support urgent intake, actual exceptional exits and narrow source-bound post-discharge corrections. Shared effective views retain original physical/identity history with coherent amendment witnesses. Doctor instructions and Nurse facts selectively invalidate affected seals; selected exception reads recheck current assignment and identity under admission ownership. Deterministic obligations and actual receipts remain separate. See [Exceptions](docs/EXCEPTIONS.md).

Transfers retain immutable versioned doctor authority and nurse handover. Admission, old/new physical beds, exact room boundaries, tariff reconciliation, holds and staff insurance task commit together. Physical bed history uses non-overlapping half-open intervals; a relevant timeline trigger serializes writers through the bed row and rejects stale repeatable-read writes. Shift closure checks its immutable transfer times. Transfer commands acquire shared settings/staff lock before staff/admission/sorted bed locks; composing callers preserve that order. See [transfers](docs/TRANSFERS.md) and [acceptance status](docs/agent/BUILD_HANDOFF.md).

Current clinical/nursing signatures use actual server time after admission ownership. Transfer withdrawal appends immutable Doctor authority and shares its effective state across care, worklists and discharge; retained earlier physical facts use the existing source-bound delayed recovery. Closed non-room reversals and missing-price performed care bind current Admin authority, original sources, proper-role effects and persisted amendment results, with native guards and unchanged historical documents. Generic room credits require physical-boundary correction. Selected professional actual facts and current return instructions constrain planned exceptional exit. Admin JSON parsing is authenticated and bounded; readiness rejects forbidden history grants. See the corresponding feature contracts for exact limits and the final review ledger for acceptance evidence.

Immutable discharge copies capture exact historical departure/seals, current attributable amendments, deterministic statements and exception ownership. Admin/Billing access is rechecked on every command and delivery. Two short source-locked transactions surround bounded local PDF rendering; publication revalidates current access, source hash and predecessor. Protected bytes, canonical source/content hashes and append-only metadata retain all versions. Room statement grouping sums recorded deltas without repricing. Native print and server PDF share the frozen model with bundled OFL Latin/Devanagari fonts. See [Documents](docs/DOCUMENTS.md) for storage, limits and native Hindi extraction qualification.

Insurance paperwork preparation uses official persistent LangGraph interruption and human review with explicitly manual, cited source text. Three bounded draft revisions retain signed history; acceptance saves one local packet and accountable follow-up without insurer communication or coverage/discharge authority. Current case/admission/document source and access are rechecked before material effects. Explicit owner checkpointer setup is separate from requests and core readiness. Invocation-local inert tracing transport prevents inherited settings from exporting source data. See [Paperwork](docs/PAPERWORK.md).

Hospital overview and role worklists use read-only repeatable-read projections over authorized current records. Stable source alerts link to existing professional actions; read-only clearance evaluation preserves command invalidation semantics. Shared hospital-IANA display/input adapters validate current server settings and preserve exact stored instants. See [Overview](docs/OVERVIEW.md) for filter, financial cohort and query limits.

`/api/health` reports application liveness. `/api/health/ready` checks the core schema/columns, limited runtime capabilities, explicit auth configuration and existing protected storage; its no-store response is only `{ "status": "ready" }` or a 503 `{ "status": "unavailable" }`. It neither applies setup nor requires optional native paperwork capability. Auth requires an explicit origin and private secret; a remote staff origin requires HTTPS. Protected storage stays in server-owned project directories, with a guarded separate synthetic recovery namespace. See the [local pilot](docs/LOCAL_PILOT.md) for complete checks and an actual independent database/storage restore. Use synthetic data until the hospital approves real policies, access, storage/retention, backup ownership and operating responsibilities.
