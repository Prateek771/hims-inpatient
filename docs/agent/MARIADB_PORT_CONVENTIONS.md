# MariaDB port conventions (branch `codex/mariadb-port`)

Target: MariaDB 11.8 (Hostinger runs 11.8.9; local dev runs 11.8.2 on 127.0.0.1:3306, no Docker). One database, no schemas. Source of truth for the final PostgreSQL shape: `tmp/port/pg-final-schema.sql` (read-only dump of `hims` and `hims_paperwork_checkpoints`; regenerate only with `pg_dump --schema-only`). **Never write to the local PostgreSQL or to Hostinger.** New MariaDB DDL lives in `web/drizzle-maria/` (do not edit `web/drizzle/`, it is the historical PostgreSQL record).

## Naming
- Drop the `hims.` prefix: `hims.admissions` -> `admissions`. Better Auth tables keep `staff_*`. Migration ledger is `hims_migrations`.
- LangGraph checkpoint tables become `lg_checkpoint_migrations`, `lg_checkpoints`, `lg_checkpoint_blobs`, `lg_checkpoint_writes` (custom saver, later).
- Constraint/index/trigger names keep the PostgreSQL names where unique per database; otherwise suffix with the table name.

## Types
| PostgreSQL | MariaDB |
|---|---|
| `uuid` (+ `gen_random_uuid()`) | `UUID` native type, `DEFAULT uuid()` |
| `timestamp with time zone` | `DATETIME(6)` holding UTC; every connection runs `SET time_zone = '+00:00'` |
| `now()` default | `DEFAULT (UTC_TIMESTAMP(6))` |
| `clock_timestamp()` in trigger bodies | `UTC_TIMESTAMP(6)` (session is UTC) |
| `jsonb` | `JSON` (alias of LONGTEXT with `JSON_VALID`); `->>` becomes `JSON_VALUE(col, '$.path')`, `jsonb_build_object` -> `JSON_OBJECT`, arrays -> `JSON_ARRAY` |
| `text` | `TEXT`, or `VARCHAR(n)` when indexed/unique (use `VARCHAR(255)`, `utf8mb4_bin` if the PostgreSQL comparison was case-sensitive) |
| `boolean` | `TINYINT(1)` |
| `numeric(p,s)`, `integer`, `bigint` | same |
| `bytea` | `LONGBLOB` |
| `text[]` / `ARRAY[...]` | `JSON` array |
| `tstzrange` overlap | explicit `start < other_end AND end > other_start` comparison |
- `CHECK` constraints stay (MariaDB enforces them). Partial indexes are not supported: use a unique index over a generated/virtual column or enforce in a trigger.
- Default charset `utf8mb4`, engine InnoDB.

## Concurrency and locking
- `pg_advisory_xact_lock(key)` has no equivalent that releases at commit. Use a lock table: `hims_locks(lock_key VARCHAR(255) PRIMARY KEY)`; take a lock with `INSERT IGNORE INTO hims_locks VALUES (?)` then `SELECT lock_key FROM hims_locks WHERE lock_key = ? FOR UPDATE`. Shared locks use `LOCK IN SHARE MODE`. App helper: `web/src/server/locks.ts` `acquireTxLock(tx, key)`.
- Session default isolation on MariaDB is READ-COMMITTED; the old "repeatable read, read only" snapshot reads set the level explicitly per transaction (`SET TRANSACTION ISOLATION LEVEL REPEATABLE READ`).
- MariaDB has no transactional DDL. Migration files must be idempotent (`IF NOT EXISTS`, `DROP ... IF EXISTS` before create for triggers) and applied one statement at a time with a ledger row written after each file.

## Triggers
- PL/pgSQL trigger functions are shared; MariaDB triggers cannot share bodies. Each `CREATE TRIGGER` carries its own body (generate repeats mechanically; keep the logic identical). `RAISE EXCEPTION 'msg'` -> `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'msg'`; keep the original message text (tests and app code match on it).
- `TG_OP` becomes separate `BEFORE INSERT/UPDATE/DELETE` triggers. `NEW`/`OLD` are the same.
- `CONSTRAINT TRIGGER ... DEFERRABLE INITIALLY DEFERRED` does not exist. List each one in `docs/agent/MARIADB_PORT_GAPS.md` with the rule it enforced and move the check into the app's final transaction step (before COMMIT), re-running the same query.
- A trigger may not modify the table that fired it; use the same-row `SET NEW.col` form, or move the write to the app and record it in the gaps file.

## Errors
- PostgreSQL SQLSTATE `23505` (unique violation) becomes MariaDB errno 1062 / `ER_DUP_ENTRY`; CHECK failure errno 4025; trigger `SIGNAL` errno 1644.

## Access model
- Hostinger gives one database user. The role split (owner vs runtime, column grants) is dropped; append-only guarantees must come from triggers, not grants. Record every guarantee that relied on grants in `docs/agent/MARIADB_PORT_GAPS.md`.

## Scratch databases for validation
- Local MariaDB root credentials are in `tmp/mariadb-local/root.env` (ignored). Create your own scratch database (`port_<yourtask>`), apply your files, drop it when done. Run the client as: `MYSQL_PWD=<from file> "/c/Program Files/MariaDB 11.8/bin/mariadb.exe" -h127.0.0.1 -uroot <db> < file.sql`. Never print the password.

## App-code patterns (wave 2; shared helpers live in `web/src/server/sql.ts`, `locks.ts`, `db.ts`)
- SQL migration files: `web/drizzle-maria/0001_tables.sql`, `0002_helpers.sql`, `0003_views.sql`, `0004_triggers.sql` (generated by `triggers/merge.mjs`; edit `T1/T2/T3.sql` and re-run it). They use `DELIMITER $$`, so any runner must honour that directive. Applied and verified together: 97 tables, 6 views, 266 triggers, 8 functions.
- Results: `rowsOf<T>(await tx.execute(sql\`...\`))` replaces `.rows`; `affectedRows(result)` for writes. Never index `[0]` ad hoc.
- No `.returning()`: `const id = newId(); await tx.insert(t).values({ id, ... }); const [row] = await tx.select().from(t).where(eq(t.id, id))` (for UPDATE: update, then re-select by key inside the same transaction, which already holds the row lock). `onConflictDoNothing()` -> `.onDuplicateKeyUpdate({ set: { <pk>: sql\`<pk>\` } })` unless a trigger would fire on the no-op update (then guard with `WHERE NOT EXISTS`, see `invalidate_clearances` in `0002_helpers.sql`).
- Locks: `pg_advisory_xact_lock(hashtextextended(k, 0))` -> `await acquireTxLock(tx, k, 'exclusive'|'shared')` with the SAME key string. The shared settings/staff lock key is exactly `'729104211'`; triggers use the keys `'729104211'`, `'availability-coordinator'`, `'doctor-directory:<uuid>'`, `'patient-identification:<uuid>'`, `'document-identity:<patient_id>'` — app code taking those locks must use identical strings.
- Errors: use `dbError(error)` -> `{ kind, errno, message }`. Rule text from triggers is in `message` (errno 1644, SQLSTATE 45000); the PostgreSQL codes 23505/23514/P0001 are gone. Update every place that matched `.code === "23505"` etc.
- Dates: raw `execute` timestamps are UTC strings; wrap with `toDate()` wherever the code needs a Date.
- Helper functions inside triggers/SQL: call as `SET @x = fn(...)`, never `DO fn(...)` (swallows errors).
- Drop the `hims.` prefix and `::type` casts in all SQL text; `now()` -> `UTC_TIMESTAMP(6)`; `ILIKE` -> `LIKE` (collation is binary: use `LOWER()` on both sides to stay case-insensitive); `array_agg` -> `JSON_ARRAYAGG`.
- Constraint-trigger rules that cannot live in the DB are listed in `docs/agent/MARIADB_PORT_GAPS.md` (sections T1/T2, 7 rules); the deferred-check module runs their detection queries before COMMIT.
- Keep behaviour identical; do not weaken or delete tests; do not commit; stay inside your assigned files and report any file outside your set that you needed to change.
- Verification DB: create your own scratch database on the local MariaDB (`tmp/mariadb-local/root.env`, never print the password), apply 0001-0004 (use the `mariadb` client for files with DELIMITER), run your checks, drop it. `npm --prefix web exec tsc -- --noEmit` is the shared typecheck; count only errors in your files.
